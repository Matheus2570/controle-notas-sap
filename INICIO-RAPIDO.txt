NOTAFLOW v1.3 — COMO COMEÇAR

TESTAR NO PC
1. Abra a pasta controle-notas-sap no VS Code.
2. Abra o terminal e execute: npm install
3. Execute: npm run dev
4. Entre no endereço que aparecer (por padrão localhost:5173).
5. Clique em "Testar visualizador" para testar o usuário SOMENTE LEITURA.
6. Em "Lançamentos", cadastre previamente SAP, Forms, site, data, quantidade e valores.
7. Em "Notas fiscais", selecione até 4 materiais e informe número da NF e chave de acesso (44 dígitos); a data de emissão já vem preenchida automaticamente. Os outros dados são preenchidos automaticamente.
8. Em "Aparência do site", mude nome, textos e cor.

COLOCAR ONLINE COM BANCO
1. Crie seu projeto no Supabase.
2. Projeto novo: rode supabase/schema.sql no SQL Editor (já inclui o fluxo de notas fiscais).
   Banco existente: se ainda não atualizou as permissões, rode supabase/roles_upgrade.sql; depois rode supabase/invoice_workflow.sql.
3. Em Authentication > Users, crie as duas contas (a sua e a de leitura).
4. No SQL Editor, promova SOMENTE a sua conta com:

   update public.app_users set role='admin'
   where user_id=(select id from auth.users where email='SEU-EMAIL@EXEMPLO.COM');

5. Desative cadastros públicos em Authentication.
6. Copie .env.example para .env e preencha com Project URL e publishable/anon key.
7. npm run dev para testar; no GitHub e na hospedagem configure as variáveis.
8. Veja README.md para instruções completas, RLS e publicação.

PERMISSÕES E CUIDADOS
- O visualizador só consulta e copia a chave; não cria, altera ou exclui. O banco bloqueia.
- O administrador pode registrar/editar notas fiscais, vinculando no máximo quatro materiais por nota.
- Os valores de SAP, Forms, site, quantidade e valores são puxados dos lançamentos existentes.
- A chave NF-e precisa ter 44 dígitos.
- Materiais já vinculados ficam protegidos contra edição/exclusão acidental.
- Não envie dados reais da empresa para serviços externos sem autorização.
